# ADR-0008: the lab's own bots - the evidence snapshot, the pins watch, the release

- Status: accepted
- Date: 2026-11-24

## Context

Dependabot moves the actions and the tools (ADR-0007), but three things of this repository are
its own: the evidence snapshot in `docs/evidence/` was copied by hand after a CI run, the pins of
`versions.yml` drift silently inside their branches (ADR-0006) and a tag was never a release.
Under the ruleset nothing lands on `main` without a pull request and seven green checks - and a
pull request opened by a workflow with `GITHUB_TOKEN` gets no workflow checks at all, so it stays
blocked for good (probed). A push with `GITHUB_TOKEN` is refused by the ruleset; the GitHub Actions
app cannot be a bypass actor of a user repository's ruleset; a deploy key can, and a push with it
lands (probed, off `main`).

## Decision

- **The evidence bot** (`evidence.yml`): after a `drills` run on `main` that was not a pull
  request, the run's artifact replaces `docs/evidence/*.json`, `SUMMARY.md` is rendered from it and
  the README's run id moves; the commit goes to `main` with a write deploy key that is the ruleset's
  bypass actor (`scripts/bot_key.sh rotate` makes the key by the API and stores the private half as
  the Actions secret `EVIDENCE_BOT_KEY`; nothing is written to disk or to git). The commit touches
  `docs/` and the README only, and lint runs on it like on any push.
- **The pins watch** (`pins-watch.yml`): weekly, the runner reads PGDG's candidates and the latest
  releases against the pins and opens an issue on a drift. An issue, not a pull request: a new branch
  is a decision (ADR-0006), and the bot's pull request would never be mergeable.
- **The release** (`release.yml`): a tag `v*` becomes a release with the snapshot's files and table.

The alternative: a fine-grained token or a GitHub App, whose pull requests do get checks. Both are
made in the browser, not by the API, and a token in a secret expires; the deploy key is one key for
one job, made and rotated by a script. Chosen for that, and named here as the weaker of the two.

## Consequences

A weekly run leaves a commit by `evidence-bot` on `main` with what it measured; the README's run
id is never stale by hand. The bypass is a write key held as a repository secret: whoever can read
secrets can push to `main` - the same people who can change the workflows. A drift is a yellow
issue, not a surprise in a red run.
